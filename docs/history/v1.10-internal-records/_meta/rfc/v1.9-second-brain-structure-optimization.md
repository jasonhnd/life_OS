# v1.9 · Second-Brain Structure Optimization

> **方针**：vault 是用户日常居住的地方，不是 lifeos 工程师的实验场。这一刀的判据只有一条 —— **用户在 Obsidian / 命令行 / git diff 里能不能更快找到他要的东西**。
>
> **透明性是核心承诺**：lifeos 系统对用户没有秘密。所有 lifeos 写入的文件 —— audit trail、SOUL snapshot、compliance log、运行时锁文件 —— 都在 `meta/` 主层可见。`meta/` 不带下划线（去除"系统目录别碰"的视觉暗示）。
>
> **md-only 约束继续**：v1.8.6 定下、v1.8.7 重申的本体论约束在 v1.9 不松动。

## §2 · 设计原则

### 2.1 核心准则

1. **Obsidian-first**：vault 的第一阅读者是人，第二阅读者是 Obsidian graph view，第三阅读者才是 lifeos agent。
2. **完全透明，无隐藏层**：lifeos 写入的所有文件都在 `meta/` 主层可见。`meta/` 不带下划线 — 透明性的 surface 体现。
3. **md-only 本体论**：继承 v1.8.6/v1.8.7。任何 .yml/.json/.sh 残留视为 bug。
4. **Wikilinks > 物理位置**：决策、项目、wiki、方法之间用 `[[id]]` 连接。
5. **Frontmatter > 目录分类**：lifecycle、type 用 frontmatter 字段表达。
6. **No surprise migrations**：所有破坏性改动必须由 `/migrate-v1.9` 显式触发。
7. **Defensive defaults, simple escape**：默认安全（如 git working dir 强制干净），但 escape hatch 慎加 — 用户主动控制（如不加并发锁、信任不并发）。

### 2.2 兼容性承诺

- v1.8.x → v1.9 迁移**只迁一次**，迁完写 `meta/config.md::migrated_to: v1.9`
- 旧路径 grep 全部消除
- 三语 docs 同步升级，失败任何一条都不算 release
- 跨版本（v1.6 / v1.7 → v1.9）**不自动 chain**，检测后中止并引导用户先跑前置迁移

## §3 · 八项优化展开

### §3.1 · Opt #1：`meta/` 透明化 + 5 类心智模型澄清

#### 3.1.1 问题

当前 `_meta/` 内容混杂（runtime / snapshots / config / 编译产物 / decisions 全在一起），用户看不清哪些是"系统写的"、哪些是"自己该读的"。下划线 `_` 前缀还隐含"系统目录别动"暗示，与透明性哲学冲突。

#### 3.1.2 提案

**两层改动**：

1. **重命名 `_meta/` → `meta/`**：去下划线。`_` 是排序约定但视觉上暗示"系统目录"，与"完全透明、邀请翻阅"哲学冲突
2. **取消 `.system/` 隐藏子层**：所有现有 `meta/` 子项保持原位、扁平共存、全部可见

**5 类心智模型**（写入 `docs/second-brain.md` § "Understanding `meta/`"，仅文档解释）：

| 类别 | 子项举例 | 谁写 | 谁读 | 保留期 |
|------|---------|------|------|------|
| **配置**（你写的） | `config.md`、`strategic-lines.md`、`extraction-rules.md`、`lint-rules.md` | 人 | 各 agent | 永久 |
| **编译产物**（系统给你看的） | `STATUS.md`、`STRATEGIC-MAP.md`、`MAP.md`、`sessions/INDEX.md`、`user-patterns.md` | retrospective / archiver / advisor | 人 + ROUTER | 重生成，可丢 |
| **精选内容**（你和系统一起写的） | `decisions/`、`journal/`、`methods/`、`queue/notifications.md` | 人 + 机器协作 | 人 + 所有 agent | 永久 |
| **审计日志**（系统的问责档案） | `compliance/violations.md`、`eval-history/`、`snapshots/soul/`、`lint-reports/`、`extraction-log.md` | agent（机器） | auditor / advisor / 人偶尔 | 长期 |
| **运行时状态**（系统的临时工作台） | `runtime/<sid>/`、`outbox/`、`.merge-lock` | agent（机器） | auditor Mode 3 | 短期（30-90 天） |

**关键决策**：

- 无 `.system/` 子目录；所有 5 类在 `meta/` 之下扁平共存
- 透明性是承诺
- `meta/` 名字去掉下划线（与既有 `_meta/` 历史所有引用都要更新，~250 处）
- size 增长可接受（典型 vault 一年 `meta/runtime/` 累积 ~5000 文件，对 git / Obsidian / 文件系统都不构成压力）

#### 3.1.3 迁移路径

`/migrate-v1.9` Stage 1 处理 `_meta/` → `meta/`：

1. `mv _meta/ meta/`（整目录重命名）
2. spec/agent/docs 全量 grep `_meta/` → `meta/`（在 Stage 2 spec 改写时一起做）

**Opt #1 的其他子项**（`.system/` 取消等）no-op，因为草案 RFC 没真正建立 `.system/`。

#### 3.1.4 影响

- **Spec/Agent**：所有 `_meta/` 引用替换为 `meta/`（~250 处 across 200+ files）
- **Docs**：`docs/second-brain.md` 加 5 类心智模型段落 + 终态目录树
- **Hooks**：N/A —— hook 层已在 v1.8.5 退役（md-only 禁 `.sh`，无 hook 文件），无路径可替换

#### 3.1.5 验收

- [ ] `_meta/` 目录在 user vault 不存在
- [ ] `meta/.system/` 目录不存在
- [ ] `git grep "_meta/"` 在 spec/agent/docs 中无 match
- [ ] `docs/second-brain.md` 含 5 类心智模型表格
- [ ] retrospective Mode 0 / archiver / auditor 跑通后 audit trail 写入 `meta/runtime/<sid>/`

### §3.3 · Opt #3：decisions 三处合一到 `meta/decisions/<YYYY-MM>/<id>.md`

#### 3.3.1 问题

- `meta/decisions/` 跨项目决策
- `projects/{p}/decisions/` 项目内决策
- `meta/incidents/<id>.no-change.yml` v1.8.5 Stage 7 "决定不改"记录

v1.8.7 forbidden_extensions 明禁 `.yml`，但 incidents 用 .yml 是矛盾。

#### 3.3.2 提案

title: <短标题>
type: change | no_change | escalation | superseded
projects: [<project-name>, ...]   # [] = 跨项目
domains: [governance | execution | finance | infra | people | growth, ...]   # Q-12 封闭枚举
reviewed_by: <agent | human>
reviewed_at: <ISO date>
decision: |
  <一句话决定>
rationale: |
  <为什么>
reopen_condition: |               # type=no_change 必填
  <什么信号触发重审>
supersedes: [<dec-id>, ...]
superseded_by: <dec-id> | null
applied_methods: [<method-name>, ...]   # Q-6 改为列表

### §3.4 · Opt #4：archive 改用 frontmatter 不物理移动

#### 3.4.1 问题

项目完成→整个 `projects/{p}/` mv 到 `archive/{p}/`，该项目内 decisions/wiki/journal 路径全变，wikilinks 失效。

#### 3.4.2 提案

**Archive 改为 frontmatter 状态**（Q-undecided-7 + Q-undecided-13 决策融合）：

```yaml
# projects/{p}/index.md frontmatter
---
project: my-old-startup
lifecycle_stage: candidate | active | archived | superseded   # Q-7: 4 值
paused_until: <ISO date> | null                                # Q-7: 新字段
created_at: <ISO date>
archived_at: <ISO date> | null
archived_at_source: git-log | migrated-unknown | manual | auto | null   # Q-13: 4 值
archived_reason: |
  <仅 archived 时必填>
strategic: [<strategic-line>, ...]
related_wiki: [[wiki/<entry>], ...]
---
```

**Lifecycle stage 语义**：

| 值 | 含义 | agent 处理 |
|------|------|------|
| **candidate** | 提议中、未真正启动 | retrospective 不计 STATUS 健康度 |
| **active** | 正在做 | 默认全部 agent 关注 |
| **archived** | 已关闭，知识沉淀完毕 | retrospective Mode 0 默认隐藏；wiki/INDEX 不过滤 |
| **superseded** | 被新项目取代 | 必须填 `superseded_by: <project-name>` |

**`paused_until` 字段**（Q-7 配套）：
- 用于"暂停但未关闭"场景（替代 v1.8.x 的 `dormant`）
- agent 检查 `paused_until > today` → 视为"active 暂停态"，不在 STATUS 警告，但 retrospective 可能提醒"到期"
- `paused_until < today` → 视为完全 active，agent 正常处理

**`archived_at_source` 4 值**：

| 值 | 触发 |
|------|------|
| **git-log** | `/migrate-v1.9` Stage 3 从 git log 取到 archive 时间 |
| **migrated-unknown** | `/migrate-v1.9` 取不到 fallback 到 today |
| **manual** | 用户手工编辑 frontmatter |
| **auto** | archiver / REVIEWER 自动归档（archive 时刻） |

**索引层做隔离**：
- retrospective Mode 0 编译 STATUS / STRATEGIC-MAP 时按 `lifecycle_stage != archived` 过滤
- archiver Phase 1 写决策/任务时同样过滤
- wiki/INDEX 不过滤

### §3.5 · Opt #5：journal 时间轴 canonical + 项目轴 wikilinks 反查

#### 3.5.1 问题

```yaml

projects: [lifeos, finance-2026]

type_tags: [briefing, dream, advisor]

```

**项目页面反查**（Q-3 + Q-8 决策：Dataview + wikilinks 双写）：

```dataview
TABLE date, type_tags

- [[meta/journal/2026-05-23]] — briefing
- ...（最新 5 条）
````

**Q-undecided-16 默认值**：

- Dataview LIMIT = **20**
- Journal split 阈值 = **1000 行**（超过则 archiver 自动拆为 `<date>-<HHMM>.md`）

#### 3.5.2.1 · DREAM 报告例外（Bug #11 决策 B，2026-05-28）

**单日单文件规则不适用于 DREAM 报告。** DREAM 报告是大段独立报告，且被 `archiver` / `retrospective` / `session-index` 通过 glob `meta/journal/*-dream.md` 读取（深度接线在 4 个文件）。强行并入单日文件需改 7 处读写点 + 24h 反重复逻辑，风险高收益低。

**决策**：DREAM 报告保持**独立 typed 文件** `meta/journal/<YYYY-MM-DD>-<slug>-dream.md`：

- 仍是 date-前缀、仍在 `meta/journal/` 之下 → 满足时间轴 canonical 的命名（verify-v1.9 check 5b 的 `YYYY-MM-DD` 前缀检查通过）
- 单日 `meta/journal/<YYYY-MM-DD>.md`（briefing / advisor / auditor section）与 `<YYYY-MM-DD>-<slug>-dream.md`（DREAM 报告）**共存**
- 单日文件的 `type_tags` 可含 `dream` 标记 + wikilink 指向当天 dream 文件（表示"当天有 DREAM"），但 DREAM 全文在独立文件
- `archiver` / `retrospective` 继续用 `meta/journal/*-dream.md` glob 读取 DREAM 报告（行为不变）

**结论**：journal 时间轴 canonical 指的是"每天的 briefing/report 类内容汇入单日文件"，DREAM 报告是这条规则的**明确例外**（独立 typed 文件，仍 date-前缀在 meta/journal/）。`dream-spec.md` 的 `<date>-<slug>-dream.md` 模型与 v1.9 一致，无需改动。

**删除 `projects/{p}/journal/`** 目录。

## §7 · Decision Records（DR-1.9）

### DR-1.9.1 · 取消 `.system/` 隐藏层 + meta/ 去下划线，全部透明可见

- **type**: change
- **decision**: `meta/` 之下无隐藏子层，所有运行时 / 审计 / 编译产物 / 配置 / 精选内容扁平共存且可见；`_meta/` 重命名为 `meta/` 去掉视觉上"系统目录"暗示
- **rationale**:
  1. md-only 哲学延伸：单用户系统，对用户没有秘密
  2. Obsidian graph view 完整性
  3. 可调试性 + 可信任
  4. 迁移成本骤降（Opt #1 从"100+ 路径迁移"变"docs 文案同步 + 单次 rename"）

### 11.2 · 关键 frontmatter schema 速查

#### 11.2.1 决策（`meta/decisions/<YYYY-MM>/<id>.md`）

```yaml
id: dec-<YYYY-MM-DD>-<NNN>
title: <short title>
type: change | no_change | escalation | superseded
projects: [<project-name>, ...]
domains: [governance | execution | finance | infra | people | growth, ...]   # 封闭枚举
reviewed_by: <agent | human>
reviewed_at: <ISO date>
decision: |
  <一句话决定>
rationale: |
  <为什么>
reopen_condition: |               # type=no_change 必填
  <什么信号触发重审>
supersedes: [<dec-id>, ...]
superseded_by: <dec-id> | null
applied_methods: [<method-name>, ...]   # 列表（可空）
journal_date: <YYYY-MM-DD>
```

#### 11.2.2 方法（`meta/methods/<name>.md`）

```yaml
name: <method-name>
domain: <governance | execution | finance | infra | people | growth>
created_at: <ISO date>
maturity: candidate | tested | canonical
born_from_decisions: [<dec-id>, ...]      # 正向：方法源自哪些决策
# applied_in_decisions: 不存在（用 Dataview + Recent 5 wikilinks 反查）
```

#### 11.2.3 项目 index（`projects/{name}/index.md`）

```yaml
project: <name>
lifecycle_stage: candidate | active | archived | superseded   # 4 值
paused_until: <ISO date> | null                                # 表达暂停语义
created_at: <ISO date>
archived_at: <ISO date> | null
archived_at_source: git-log | migrated-unknown | manual | auto | null   # 4 值
archived_reason: |
  <仅 archived 时必填>
strategic: [<strategic-line>, ...]
related_wiki: [[wiki/<entry>], ...]
```

#### 11.2.4 Journal（`meta/journal/<YYYY-MM-DD>.md`）

```yaml
date: <ISO date>
projects: [<project-name>, ...]
session_ids: [<sid>, ...]
type_tags: [briefing, dream, advisor, auditor, migration, ...]
referenced_decisions: [<dec-id>, ...]
referenced_methods: [<method-name>, ...]
```
