# Scenario: F11 — i18n diff parity check 9

## Purpose

Verify verify-release check 9 correctly detects EN ↔ zh / EN ↔ ja diff drift in `references/*.md` between two tags, outputs WARN level in v1.8.7, and respects exception frontmatter.

## Test cases

### Case 1: Aligned changes — PASS

**Given**: EN spec section changed; zh + ja mirrors changed in matching section + same commit.

**Expected behavior**:
- check 9 identifies changed section in EN
- Verifies same section diff in zh + ja
- Verifies section count parity (count(EN `##`) == count(zh `##`) == count(ja `##`))
- Output: ✅ PASS

**Expected verdict**: PASS.

### Case 2: Drift — EN updated, zh/ja unchanged

**Given**: `references/concept-spec.md` changed in commit; `i18n/zh/references/concept-spec.md` and `i18n/ja/references/concept-spec.md` not touched between `<base>..HEAD`.

**Expected behavior**:
- check 9 detects mismatch
- Output (v1.8.7): ⚠️ WARN with list of drifted (file, section) pairs
- Release ALLOWED to proceed (WARN does not block in v1.8.7)
- Drift recorded for follow-up

**Expected verdict**: WARN (not FAIL) in v1.8.7.

**Expected v1.8.8 verdict**: would be FAIL (BLOCK) after WARN→BLOCK promotion.

### Case 3: Section count parity violation

**Given**: EN spec adds new `## ` section; zh adds the section but ja does not.

**Expected behavior**:
- check 9 detects count(EN) == 5, count(zh) == 5, count(ja) == 4
- Output: ⚠️ WARN — `i18n/ja/references/<file>.md` missing section "<name>"
- Specific failure: section count parity violation

**Expected verdict**: WARN; flagged for v1.8.8 BLOCK promotion category.

### Case 4: Exception — anchor-only adjustment

**Given**: Changes limited to adding English anchor to translated section titles (e.g. `## 背景` → `## 背景 (Background)`); no substantive content change.

**Expected behavior**:
- check 9 reads frontmatter `i18n_parity_exception: anchor-only`
- Skips mirror verification for this commit
- Output: ✅ PASS (exception honored)

**Expected verdict**: PASS.

### Case 5: Translation-only commit

**Given**: Commit fixes typos in `i18n/zh/references/*.md` without touching EN.

**Expected behavior**:
- check 9 detects no EN diff
- Skips mirror verification (translation-only commits are self-correcting)
- Output: ✅ PASS

**Expected verdict**: PASS.

### Case 6: Legacy spec exempt

**Given**: `references/concept-spec.md` has `status: legacy` frontmatter; EN changed but mirrors not touched.

**Expected behavior**:
- check 9 reads `status: legacy`
- Recognizes legacy specs don't require ongoing parity (content frozen)
- Output: ✅ PASS (legacy exception)

**Expected verdict**: PASS.

## Scope notes

- Section identification uses `## ` second-level headings; line-level diff is too granular.
- 3-commit window tolerance allows EN + zh + ja to land across 1-3 sequential commits in same PR.
- AUDITOR Mode 7 M7-5 runs this same check at session-end on the most recent commit (lightweight version).
