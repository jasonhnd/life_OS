# Scenario: v1.9 wikilink preservation after archive→frontmatter

## Purpose

Verify Opt #4 (archive改为 frontmatter，不物理移动) preserves all wikilinks pointing into archived projects. Pre-v1.9 archive moved `projects/{p}/` → `archive/{p}/`, breaking all `[[projects/{p}/...]]` links. v1.9 must keep these links resolvable.

---

## Test cases

### Case 1: Wiki entry references archived project's decision

**Given**:
- v1.8.7 vault before migration:
  - `archive/old-startup/decisions/v1-launch.md` (archived project's decision)
  - `wiki/startup-lessons.md` contains: `参见 [[projects/old-startup/decisions/v1-launch]]`
- User runs `/migrate-v1.9`

**Expected behavior** (Stage 3 + Stage 2):
- Stage 3: `archive/old-startup/` moves back to `projects/old-startup/` with `lifecycle_stage: archived`
- Stage 2: `projects/old-startup/decisions/v1-launch.md` migrates to `meta/decisions/<YYYY-MM>/<id>.md`
- Wikilink `[[projects/old-startup/decisions/v1-launch]]` becomes ambiguous: target file moved
- Obsidian wikilink resolution: by filename, resolves to new location (`v1-launch` matched in `meta/decisions/`)

**Expected verdict**: PASS if Obsidian opens vault post-migration AND wikilink `[[projects/old-startup/decisions/v1-launch]]` still resolves (no red link), OR migration tool also rewrites these refs

**Note**: Strict pre-v1.9 path forms (`[[projects/old-startup/decisions/v1-launch]]`) may still red-link; preferred wikilink form is filename-only (`[[v1-launch]]`) which Obsidian resolves automatically. v1.9 RFC accepts this trade-off — wikilink rewriting can be added in v1.9.x patch if needed.

### Case 2: SOUL.md references archived project by short wikilink

**Given**:
- `SOUL.md` contains: `从 [[old-startup]] 的失败学到` (short wikilink, no path prefix)
- After `/migrate-v1.9`, `archive/old-startup/` moved back to `projects/old-startup/` with `lifecycle_stage: archived`

**Expected behavior**:
- Wikilink `[[old-startup]]` resolves to `projects/old-startup/index.md` (unchanged file path post-Stage 3)
- No red link

**Expected verdict**: PASS

### Case 3: Strategic-line references archived project

**Given**:
- `meta/strategic-lines.md` contains:
  ```markdown
  ## 长期影响力扩展
  - [[projects/old-startup]]
  - [[projects/lifeos]]
  ```
- After migration, `old-startup` has `lifecycle_stage: archived`
- User next session runs `/上朝`

**Expected behavior** (per Q-undecided-10 / DR-1.9.23):
- retrospective Mode 0 compiles `meta/STRATEGIC-MAP.md`
- archived project displayed with strikethrough + `(archived <date>)` marker:
  ```markdown
  ## 长期影响力扩展
  - ~~old-startup~~ (archived 2024-11-03) → 历史
  - lifeos (active, ...) → 健康度: 高
  ```
- Bottom of briefing includes ⚠ cleanup prompt
- Both wikilinks resolve (no red link)

**Expected verdict**: PASS if both display formats render AND wikilinks resolve

**Expected failure_class on miss**:
- archived项目 filtered out entirely = `F4 SCOPE_FAILURE` (Q-10 chose mark+prompt, not filter)
- archived项目 shown normally without marker = `F4 SCOPE_FAILURE`

### Case 4: Obsidian graph view colorGroup for archived projects

**Given**:
- Vault has `.obsidian/graph.json` with existing colorGroups
- User runs `/migrate-v1.9`

**Expected behavior** (Stage 3 step 4):
- `.obsidian/graph.json` gets new colorGroup appended:
  ```json
  {
    "query": "path:projects/ AND tag:archived",
    "color": {"a": 1, "rgb": 11448499}
  }
  ```
- Existing colorGroups preserved (no overwrite)
- Post-migration Obsidian graph view shows archived projects in grayed color

**Expected verdict**: PASS if archived colorGroup added AND existing groups preserved
