# Scenario: A3 — concept-spec hotness thresholds made explicit

## Purpose

Verify v1.8.7 documents hotness thresholds explicitly in `references/concept-spec.md` AND that behavior is UNCHANGED from v1.8.6 (this is a documentation-only change).

## Test cases

### Case 1: Hotness rationale section present

**Given**: `references/concept-spec.md` shipped in v1.8.7.

**Expected behavior**:
- File contains `### Hotness thresholds rationale (v1.8.7 explicit per RFC §2.7 A3)` section after Promotion table
- Section enumerates 3 thresholds: ≥3 sessions → confirmed, ≥10 → canonical, 90-day dormancy → retirement candidate
- Each threshold has explicit *rationale* paragraph (not just the number, but why this number)
- Section explicitly states "Behavior unchanged from v1.8.6 — only the documentation surface elevated"

**Expected verdict**: PASS if rationale section present AND all 3 thresholds documented AND behavior-unchanged disclaimer present.

**Expected failure_class on miss**: `F3 SCHEMA_FAILURE` if rationale section missing.

### Case 2: Three-language mirror parity

**Given**: v1.8.7 ship state.

**Expected behavior** (verify-release check 9):
- `i18n/zh/references/concept-spec.md` contains 同名 rationale 段
- `i18n/ja/references/concept-spec.md` contains 同名 rationale section
- All three languages have section count parity
- Section ordering matches

**Expected verdict**: PASS (or WARN at most under v1.8.7 default level).

### Case 3: knowledge-extractor behavior unchanged

**Given**: A session that activates several concepts.

**Expected behavior**:
- `agents/knowledge-extractor.md` (and archiver Phase 2 Concept Extraction logic) uses same ≥3 / ≥10 / 90-day numbers as before v1.8.7
- No new auto-materialization (no automatic summary file generation when concept hits canonical)
- Promotion remains MANUAL-triggered (knowledge-extractor decides, not auto-fired)

**Expected verdict**: PASS if behavior diff between v1.8.6 and v1.8.7 archiver/extractor is exactly zero on this code path.

**Expected failure_class on miss**: spec → implementation drift = `F12 DRIFT_FAILURE`.

### Case 4: Pattern source attribution present

**Given**: concept-spec.md rationale section review.

**Expected behavior**:
- Section mentions OpenHuman hotness-driven topic materialization as pattern source
- States lifeos adopted the *concept* (hotness) but stays manual-trigger (not auto-materialize)
- Cross-reference to RFC §2.7 A3 for rationale on staying manual

**Expected verdict**: PASS if attribution present.

## Scope notes

- This is the smallest scenario in v1.8.7 because A3 is documentation-only. The real value is making promotion semantics auditable.
- If future versions actually change promotion thresholds, this scenario expands to verify the new numbers — and the rationale must be updated FIRST (per concept-spec.md spec discipline).
