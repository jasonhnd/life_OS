# Scenario: B5 — evals_scenarios required field in planning docs

## Purpose

Verify `dispatcher` correctly rejects planning documents missing or with invalid `evals_scenarios:` frontmatter field, while accepting valid configurations (including N/A enum and TBD with deadline).

## User Message

```
The planning doc is ready for dispatch. Before sending work to domains, validate its `evals_scenarios` frontmatter and reject any missing, empty, invalid N/A, non-existent, or stub fixture entry with the correct F4 SCOPE_FAILURE.
```

## Test cases

### Case 1: Valid path entry — PASS

**Given**: Planning doc with `evals_scenarios: [evals/scenarios/existing-fixture.md]` where the file exists.

**Expected behavior**:
- dispatcher reads frontmatter
- Verifies path exists via `test -f`
- Accepts and proceeds to dispatch

**Expected verdict**: PASS.

### Case 2: Empty list — REJECT

**Given**: Planning doc with `evals_scenarios: []`.

**Expected behavior**:
- dispatcher detects empty list
- Outputs `F4 SCOPE_FAILURE: planning doc <path> missing or invalid evals_scenarios — empty list`
- Halts dispatch
- Returns to planner

**Expected verdict**: REJECT; `F4 SCOPE_FAILURE`.

### Case 3: Missing field entirely — REJECT

**Given**: Planning doc frontmatter without `evals_scenarios:` key.

**Expected behavior**:
- dispatcher treats as empty list
- Same as Case 2: `F4 SCOPE_FAILURE`

**Expected verdict**: REJECT; `F4 SCOPE_FAILURE`.

### Case 4: Valid N/A with enum reason — PASS

**Given**: Planning doc with `evals_scenarios: ["N/A: docs-only"]`.

**Expected behavior**:
- dispatcher checks enum: `docs-only` IS in allowed set (`docs-only / pure-translation / i18n-mirror-update / typo-fix / cleanup-only`)
- Accepts

**Expected verdict**: PASS.

### Case 5: Invalid N/A reason — REJECT

**Given**: Planning doc with `evals_scenarios: ["N/A: trust me"]` or `N/A: see below` or `N/A: TBD`.

**Expected behavior**:
- dispatcher checks enum: `trust me` / `see below` / `TBD` NOT in allowed set
- Outputs `F4 SCOPE_FAILURE: planning doc <path> invalid N/A reason; pick from enum or write scenario`
- Halts dispatch

**Expected verdict**: REJECT; `F4 SCOPE_FAILURE`.

### Case 6: Path to non-existent fixture — REJECT

**Given**: Planning doc with `evals_scenarios: [evals/scenarios/this-does-not-exist.md]`.

**Expected behavior**:
- dispatcher verifies path exists; file not found
- Outputs `F4 SCOPE_FAILURE: planning doc <path> references non-existent fixture <path>`
- Halts dispatch

**Expected verdict**: REJECT; `F4 SCOPE_FAILURE`.

### Case 7: Valid TBD with deadline — PASS at dispatch, REJECT at reviewer-final

**Given**: Planning doc with `evals_scenarios: ["TBD: evals/scenarios/v1.8.8-name.md (commit-by: v1.8.8)"]`.

**Expected behavior**:
- dispatcher detects TBD with parseable `commit-by:` clause
- Accepts (downstream can proceed)
- Logs as `pending_scenarios` in dispatch order
- reviewer-final later checks: if TBD not resolved by ship time → `F10 RESPONSIBILITY_FAILURE`

**Expected verdict**: PASS at dispatch; REJECT at reviewer-final if not resolved.

### Case 8: Stub fixture (≤30 lines or ≤1 acceptance criterion) — effectively empty

**Given**: Planning doc with `evals_scenarios: [evals/scenarios/smoke-test.md]` where the file exists but contains only "TODO".

**Expected behavior**:
- dispatcher detects fixture file is stub (< threshold)
- Treats as empty
- Outputs `F4 SCOPE_FAILURE: fixture <path> is stub (< 30 lines / < 1 acceptance criterion)`

**Expected verdict**: REJECT; `F4 SCOPE_FAILURE`.

## Scope notes

- This scenario verifies dispatcher's hard gate. The actual fixture content quality is the planner's and reviewer's responsibility.
- Allowed N/A reasons are an explicit enum — adding new reasons requires updating `references/feature-workflow-spec.md` and this scenario.
