# Scenario: Karpathy-borrowed behavioral principles + default anti-patterns

## Purpose

Verify v1.8.7 within-release Karpathy borrow is present and correctly attributed:
1. SKILL.md top contains `## Behavioral Principles` section with 4 principles + `Tradeoff:` line + `The test:` lines + Karpathy attribution
2. references/agent-spec.md contains `## Default Anti-patterns` section with DA-1 through DA-3 + override mechanism
3. Three-language alignment (zh + ja mirrors of agent-spec.md)
4. AUDITOR Mode 6 extended checks (DA-1/DA-2 enforcement) referenced

## Test cases

### Case 1: SKILL.md Behavioral Principles section present

**Given**: v1.8.7 within-release ship state.

**Expected behavior**:
- SKILL.md contains `## Behavioral Principles` H2 heading
- 4 principles enumerated with their Karpathy-original names: "Think Before Coding" / "Simplicity First" / "Surgical Changes" / "Goal-Driven Execution"
- Each principle has a `The test:` line (single-sentence sanity check)
- Section opens with `Tradeoff:` line
- Section ends with `### Attribution` referencing `multica-ai/andrej-karpathy-skills` MIT-licensed source
- Section is placed BEFORE `## Theme System` (top-of-file placement for onboarding)

**Expected verdict**: PASS.

**Expected failure_class on miss**: `F3 SCHEMA_FAILURE: SKILL.md missing Behavioral Principles section or attribution`.

### Case 2: agent-spec Default Anti-patterns DA-1 through DA-3

**Given**: references/agent-spec.md ship state.

**Expected behavior**:
- File contains `## Default Anti-patterns` H2 section before `## Source attribution`
- DA-1 enumerated: "Notice unrelated dead code, mention but don't delete"
- DA-2 enumerated: "Match existing style even if you'd do it differently"
- DA-3 enumerated: "Surface tradeoffs explicitly when proposing changes"
- Override mechanism documented: `default_anti_patterns_override` frontmatter field
- Examples of legitimate overrides listed (wiki-decay, memory-keeper)
- AUDITOR Mode 6 enforcement extension noted for each DA

**Expected verdict**: PASS if all 3 DAs documented + override mechanism + Mode 6 enforcement.

**Expected failure_class on miss**: `F3 SCHEMA_FAILURE: agent-spec.md missing Default Anti-patterns section`.

### Case 3: Three-language mirror parity for agent-spec.md

**Given**: agent-spec.md ship state.

**Expected behavior**:
- `references/agent-spec.md` Default Anti-patterns section present (English)
- `i18n/zh/references/agent-spec.md` 默认反模式 section present (Chinese)
- `i18n/ja/references/agent-spec.md` デフォルトアンチパターン section present (Japanese)
- Section count parity per `references/i18n-diff-parity-spec.md` (v1.8.7 F11)
- DA-1, DA-2, DA-3 IDs preserved across languages (untranslated for cross-reference)

**Expected verdict**: PASS if 3-language alignment holds.

**Expected failure_class on miss**: WARN per v1.8.7 i18n diff parity check 9 (BLOCK target v1.8.8).

### Case 4: Spec writing conventions adopted

**Given**: Any new spec authored from v1.8.7 within-release commit ae5284e onward.

**Expected behavior** (soft contract):
- New spec includes `Tradeoff:` line acknowledging what the rule biases against
- New spec includes `The test:` line with single-sentence sanity check
- v1.8.7 examples: `references/status-line-spec.md` / `references/conscious-patrol-spec.md` / `references/feature-workflow-spec.md` / `references/agent-spec.md` Default Anti-patterns section

**Expected verdict**: PASS if v1.8.7 new specs adopt convention. (Existing specs not retroactively flagged.)

**Expected failure_class on miss (NEW specs only)**: WARN level (soft contract, not hard gate).

### Case 5: Override declaration for cleanup-role agents

**Given**: An agent file (e.g. future refactor-cleaner / current wiki-decay prompt) whose role legitimately requires deletion.

**Expected behavior**:
- Agent frontmatter contains `default_anti_patterns_override:` key
- Each overridden DA enumerated with justification citing role spec
- AUDITOR Mode 6 reads override frontmatter and skips enforcement for that agent's declared exemptions

**Expected verdict**: PASS if override declared with justification.

**Expected failure_class on miss**: `F4 SCOPE_FAILURE: agent claims deletion behavior without DA-1 override declaration` OR `F4: override without role-spec basis`.

### Case 6: lifeos-original enforcement preserved (not lost in borrow)

**Given**: lifeos's existing enforcement mechanisms for the 4 Karpathy principles.

**Expected behavior** — SKILL.md Behavioral Principles section maps each Karpathy principle to lifeos's pre-existing enforcement:
- P1 Think Before Coding → ROUTER intent clarification + Risk Domains + REVIEWER + COUNCIL + R5 fact-check
- P2 Simplicity First → Minimality Rule + DR-09 product quality + DR-08 cargo-cult cuts
- P3 Surgical Changes → blast_radius + AUDITOR Mode 6 + WHEN-NOT-TO-ADD + NEW DA-1/DA-2/DA-3
- P4 Goal-Driven Execution → B5 evals_scenarios + reviewer-final + self-driven loops + method library

**Expected verdict**: PASS if each principle has lifeos enforcement listed (proves borrow is integration not replacement).

## Scope notes

- This scenario verifies the v1.8.7 within-release Karpathy-borrow is correctly documented and integrated, NOT that the principles are followed at runtime (that requires per-agent runtime audits via Mode 6).
- The 4 principles are mostly already covered by lifeos's pre-existing 22-agent machinery. The borrow's value is in onboarding clarity (top-of-SKILL summary) + filling DA-1 gap (notice dead code, mention not delete).
- v1.8.7 keeps version unchanged per user instruction "bug 没修好不能有任何版本升级". Tag v1.8.7 stays at 18e802a; this commit extends within the v1.8.7 framework.
