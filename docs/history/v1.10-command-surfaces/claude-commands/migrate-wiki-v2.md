# /migrate-wiki-v2

Interactive migration of wiki/ entries from v1 schema to v2 schema per `references/wiki-spec.md` v2. **Idempotent**: re-running on a partially-migrated wiki adds v2 frontmatter to any v1 entry that lacks it; never overwrites existing v2 frontmatter.

## Pre-flight

### 1. Locate wiki dir
```bash
WIKI_DIR="${1:-}"
if [ -z "$WIKI_DIR" ]; then
  if [ -d "./wiki" ]; then WIKI_DIR="./wiki"
  elif [ -d "$HOME/SecondBrain/wiki" ]; then WIKI_DIR="$HOME/SecondBrain/wiki"
  fi
fi
```
If not found → emit `❌ wiki/ not found; pass path as $ARGUMENTS or cd into vault root first` and exit.

### 2. List entries
```bash
ls "$WIKI_DIR"/*.md 2>/dev/null
```
Exclude `INDEX.md`, `log.md`, `.templates/`, files starting with `.`.

### 3. Inventory each entry
For each file, check if v2 frontmatter present (look for `id: wn-*` AND `classification:` AND `operating_hypothesis:`). If yes → skip (idempotent).

### 4. Backup (mandatory — HARD RULE, before any edit)
Copy the entire wiki dir before touching a single entry:
```bash
TS=$(date +%Y%m%d-%H%M%S)
cp -r "$WIKI_DIR" "${WIKI_DIR}.v1-backup-${TS}"
```
If the copy fails, abort with `❌ backup failed — refusing to migrate in place` and do NOT edit any entry. The success summary's `Backup:` line reports `${WIKI_DIR}.v1-backup-${TS}`.

## Per-entry migration loop

For each v1 entry needing v2 frontmatter:

### Step 1: Display current entry summary

```
── Migrating wiki entry: <filename>.md ──
Title: <first H1 line>
Body length: <N lines>
First 200 chars of body: <preview>
```

### Step 2: Ask 6 facets classification

Use AskUserQuestion (one question for each ambiguous facet; auto-fill the obvious ones):

**function** (mostly inferable from entry content; auto-suggest then confirm):
- if entry describes "how to do X" → `specify`
- if entry describes "X is a fact about Y" → `validate`
- if entry describes "X usually causes Y" → `diagnose`
- otherwise ask user

**target_object** (always ask):
```
Question: What is this entry "about"? (one short noun phrase)
Example: "Japanese NPO lending law", "trust structure tax implications"
```

**automation_mode**: usually `human_executed` for wiki entries (humans read and apply). Auto-fill.

**authority_level**: `suggest_only` for wiki entries (advice, not directive). Auto-fill.

**risk_level** (ask if subject in `references/risk-domains.md` 8 domains):
- If subject touches finance/health/legal/safety/children/public claims/publication/governance → ask user low/medium/high/critical
- Otherwise → default `low`

**lifecycle_stage**: legacy v1 entries default to `active`. Confirm with user.

### Step 3: Ask operating_hypothesis

Use AskUserQuestion:
```
Question: Reformulate this entry as a falsifiable hypothesis. Given X, this entry should produce Y within risk R. Example: "Given a Japanese NPO considering a lending product, this entry should warn that 貸金業法 has no NPO exemption (small or large), within risk of regulatory penalty."

Header: operating_hypothesis
Options:
  - label: "<auto-generated from title + first paragraph>"
  - label: "Other (type)"
```

Reject if user input < 30 chars.

### Step 4: Identify outlier reference

Use AskUserQuestion:
```
Question: Find at least one "outlier" — a case/work/person you dislike but who succeeded in the area this entry covers. (anti-confirmation-bias defense)
Example for "compounding investing is best": outlier = "WSB-style options gambling, which I find reckless but several people made fortunes with it in 2021."

Header: outlier
Options:
  - label: "Skip for now (lifecycle stays candidate until filled)"
  - label: "Other (specify ref + why)"
```

If skipped → flag entry `outlier_pending: true`, demote lifecycle_stage to `candidate` if it was `active`.

### Step 5: Ask arguments_against

Use AskUserQuestion:
```
Question: Why might this entry be WRONG? What observable signal would falsify it? (must be specific — "could be wrong" not accepted)

Header: arguments_against
Options:
  - label: "<auto-suggest: 'Watch for cases where X did not hold, e.g....'>"
  - label: "Other (type)"
```

Reject if < 20 chars OR contains only trivial phrases ("could be wrong", "no counter-evidence", "TBD", "未知").

### Step 6: Write v2 frontmatter

Prepend v2 frontmatter to the entry. Preserve full v1 body below. Mark with comment:

```yaml
---
# v2 migration added by /migrate-wiki-v2 on YYYY-MM-DD
id: wn-<auto-slug-from-filename>
name: "<entry title>"
version: "0.1.0"

classification:
  function: <user's pick>
  target_object: "<user's answer>"
  automation_mode: human_executed
  authority_level: suggest_only
  risk_level: <user's pick>
  lifecycle_stage: <user's pick, default active>

operating_hypothesis: |
  <user's answer>

context_manifest:
  source_of_truth: []   # populate during next reference
  supporting: []
  forbidden: []

reference_set:
  aspirational: []
  anti_reference: []
  boundary_case: []
  mainstream_baseline: []
  outlier:
    - ref: "<user's ref>"
      why: "<user's why>"

failure_modes:
  known: []
  warning_signs: []
  repair_actions: []

arguments_against: |
  <user's answer>

confidence: <from v1, if absent default 0.5>
evidence_count: <from v1, if absent default 0>
challenges: <from v1, if absent default 0>
created: <from v1, if absent infer from git log first commit>
last_validated: <today>
source: migrated-from-v1
v1_legacy: true
---

<original v1 body preserved here>
```

Do NOT modify v1 body content. Only prepend frontmatter.

## After all entries migrated

### Update INDEX.md

If `wiki/INDEX.md` exists, rebuild it with v2 metadata visible:
- Group by `lifecycle_stage`
- Within each group, sort by `last_validated DESC`
- Show `target_object` next to title

### Final validation

Invoke `/audit --mode 5`, or launch AUDITOR Mode 5 inline if the slash trigger is unavailable (AUDITOR Mode 5 wiki schema audit). Validates:
- W1: every entry has 7 v2 required field groups
- W2: every `active+` entry has non-empty outlier
- W3: arguments_against non-trivial
- W4: lifecycle_stage matches usage evidence

If pass → emit:
```
✅ /migrate-wiki-v2 done.
   Migrated N v1 entries to v2 frontmatter.
   K entries flagged outlier_pending (demoted to candidate).
   Backup: <WIKI_DIR>.v1-backup-<ts>/
```

If fail → list per-entry issues + offer to re-prompt user.

## HARD RULES

- **Interactive only** — every entry requires user confirmation. No `--auto` flag.
- **Idempotent** — re-running on partial migration only touches v1-only entries.
- **Never deletes v1 body** — frontmatter is prepended; body untouched.
- **Backup mandatory** — copy entire `wiki/` to `wiki.v1-backup-<ts>/` before any edit.
- **outlier required for active+** — if user skips, demote to `candidate` automatically.
- **arguments_against cannot be trivial** — slash rejects "could be wrong"-class answers.
