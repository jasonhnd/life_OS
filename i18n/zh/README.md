# Life OS

Life OS 是一个由大模型自主选择方法、由用户掌控目标和边界的个人操作系统。
它可以协助决策、规划、复盘、研究、知识整理，以及跨会话的本地 Markdown
记忆。

根目录 `SKILL.md` 是唯一的通用运行时权威。

## 大模型主权

在用户授权的范围内，大模型可以自行判断：

- 直接回答，还是读取更多相关上下文；
- 是否使用工具、Shell、CLI、应用或连接器；
- 不使用 agent、使用现有模板，还是创建临时专家；
- 如何拆分工作、验证到什么深度、怎样呈现结果。

Life OS 不要求固定的 ROUTER → PLANNER → REVIEWER 流程，也不要求斜杠命令、
状态行、审计文件或固定验证器。

这里的自主权只适用于“方法”。目标、工作区、私人数据和重要外部操作仍由
用户决定。大模型不能擅自扩大范围，也不能因为用户说“完成”或“结束”就推送、
发布、发送、删除或迁移。

## 完整模式与对话模式

完整模式需要明确绑定一个用户选定的本地 Markdown 目录作为第二大脑。

这个目录不需要 Git、远程仓库、干净的工作树或网络。Git 只是可选的版本记录
和同步工具。

没有绑定时，Life OS 仍然可以在当前对话中分析、规划和研究，但必须如实说明
这是“仅对话模式”，不能声称拥有持久记忆。

Life OS 的开发仓库不是第二大脑。普通项目仓库也不会因为使用 Git 就自动变成
第二大脑。

## 开始使用

让你的 AI 宿主能够读取本仓库根目录的 `SKILL.md`，然后直接用自然语言提出
目标：

> 帮我比较下面两个方案。只使用我在当前对话中提供的信息。

如果需要持久化，先在宿主中选定本地 Markdown 目录，再明确说：

> 把我选定的本地目录绑定为本次会话可读写的第二大脑。请阅读我指定的项目
> 文档，并把最终决定保存回该项目。

这只授权所说的本地写入，不自动授权 Git commit、push 或发布。

## Agent、主题与宿主

`agents/` 中的文件都是可选分析模板。大模型可以跳过、组合、改写或创建临时
角色。简单任务不需要为流程而调用 agent。

`themes/` 只改变展示名称、语言、语气和标题，不改变权限、安全、持久化或
工作流。

`hosts/` 只说明各宿主具备什么能力以及如何降级，不会改变 Life OS 的产品
语义。没有 Shell 或子代理的宿主仍然可以直接完成适合的任务。

## 验证与完成

验证深度应与风险和完成声明相匹配。小型本地文档修改可以用聚焦 diff；迁移、
外部操作、高风险建议和发布需要更强证据。

重要的完成报告应区分：观察到什么、改了什么、验证了什么、什么没有验证、
还有什么受阻。
