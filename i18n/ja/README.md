# Life OS

Life OS は、手段の選択を実行時モデルに委ね、目的と境界をユーザーが管理する
個人向けオペレーティングシステムです。意思決定、計画、振り返り、調査、
知識整理、ローカル Markdown による継続的な記憶を支援します。

リポジトリ直下の `SKILL.md` が、唯一の共通ランタイム権威です。

## モデル主権

ユーザーが許可した範囲で、モデルは次の方法を選べます。

- 直接回答するか、関連する文脈を追加で読むか；
- ツール、Shell、CLI、アプリ、コネクターを使うか；
- agent を使わないか、既存テンプレートまたは臨時専門家を使うか；
- 作業の分割、検証の深さ、結果の見せ方。

固定の ROUTER → PLANNER → REVIEWER 手順、スラッシュコマンド、ステータス
行、監査ファイル、特定の検証ランナーは必要ありません。

この自由は手段に限られます。目的、ワークスペース、個人データ、重要な外部
操作はユーザーが管理します。「完了」「終了」だけから push、公開、送信、
削除、移行の許可を推測しません。

## Full Mode と Conversation-Only Mode

Full Mode には、ユーザーが明示的に選んだローカル Markdown ディレクトリを
second-brain としてバインドする必要があります。

Git、remote、clean worktree、ネットワークは必須ではありません。Git は任意
の履歴・同期アダプターです。

バインドがなくても、現在の会話で分析、計画、調査を支援できます。ただし
Conversation-Only Mode と正直に示し、永続的な記憶を主張しません。

Life OS の開発リポジトリや通常の Git プロジェクトを second-brain と推測
しません。

## 始め方

AI ホストからリポジトリ直下の `SKILL.md` を読めるようにし、自然言語で目的
を伝えます。

> 次の二つの案を比較してください。この会話で渡した情報だけを使ってください。

永続化する場合は、ローカル Markdown ディレクトリを選択したうえで明示します。

> 選択したローカルディレクトリを、このセッションの読み書き可能な
> second-brain としてバインドしてください。指定するプロジェクトノートを
> 読み、最終決定を保存してください。

この依頼は Git commit、push、公開を自動的には許可しません。

## Agent、テーマ、ホスト

`agents/` は任意の分析テンプレートです。モデルは省略、組み合わせ、変更、
または臨時ロールの作成ができます。

`themes/` は表示名、言語、トーン、見出しだけを変えます。権限、安全、
永続化、ワークフローは変えません。

`hosts/` はホスト能力とフォールバックだけを説明します。Shell や subagent
がないホストでも、適切な作業を直接実行できます。

## 検証と完了

検証の深さはリスクと主張に合わせます。重要な完了報告では、観察したこと、
変更したこと、検証したこと、未検証のこと、残る阻害要因を区別します。
