# Scenario: v1.9 migration end-to-end correctness

## Purpose

Verify `/migrate-v1.9` correctly handles all 8 Opts in sequence (Stage 1 → Stage 7 + finalize), respects Pre-flight HARD GATEs, produces a deterministic v1.9 layout, and `/verify-v1.9` confirms all 8 acceptance checks PASS.

---

## Test cases

### Case 1: Happy path — clean v1.8.7 vault migrates to v1.9

**Given**:
- Vault on `migrated_to: v1.8.7` with normal contents:
  - 5 active projects in `projects/`
  - 2 archived projects in `archive/`
  - `_meta/inbox/{to-process/,notifications.md}`
  - `projects/*/decisions/` with ~15 total decisions
  - `_meta/incidents/*.no-change.yml` with 3 entries
  - `projects/*/journal/` with ~30 total entries
  - `meta/methods/` with 4 methods
  - `user-patterns.md` at vault root
  - All `lifecycle_stage: candidate|active|dormant|archived`
  - Git working dir clean
- User runs `/migrate-v1.9`

**Expected behavior**:
- Stage 0a passes (git clean)
- Stage 0b passes (migrated_to: v1.8.7, valid)
- Stage 0c passes (no archive non-project content)
- Dry-run shows per-stage summary (no per-file list)
- User confirms `go`
- Stage 1: `_meta/` → `meta/` rename
- Stage 1.5: `meta/inbox/` → `meta/queue/`
- Stage 2: All decisions migrate to `meta/decisions/<YYYY-MM>/<id>.md`; incidents .yml convert to .md
- Stage 3: archive/* moved back to projects/* with `lifecycle_stage: archived` + `archived_at` + `archived_at_source`
- Stage 4: journal entries merge to `meta/journal/<date>.md`
- Stage 5: areas reseed README
- Stage 6: user-patterns.md → meta/
- Stage 7: cross-reference fields added; method pages get Dataview section
- Stage 8.1: config.md::migrated_to: v1.9
- Stage 8.2: migration report appended to today's journal (type_tags含 migration)
- Stage 8.3: git commit "chore(v1.9): migrate vault to v1.9 layout"
- Total runtime < 60s for vault with ~50 files

**Expected verdict**: PASS if all 8 stages complete + commit created + `/verify-v1.9` returns exit 0 with all 8 ✅

**Expected failure_class on miss**:
- Any stage skipped silently = `F10 RESPONSIBILITY_FAILURE`
- Stage report incomplete in journal = `F4 SCOPE_FAILURE`

### Case 2: Pre-flight reject — git working dir not clean

**Given**:
- Vault on v1.8.7, but `git status --porcelain` returns non-empty (uncommitted edits to wiki/)
- User runs `/migrate-v1.9`

**Expected behavior**:
- Stage 0a fails immediately
- Output: "❌ 检测到未提交改动... please git stash or git commit"
- NO further stages execute
- Vault state unchanged
- Exit code 1

**Expected verdict**: PASS if rejection happens before Stage 1 AND error message includes both `git stash` and `git commit` options

**Expected failure_class on miss**: bypass of HARD GATE = `F2 INPUT_VALIDATION_FAILURE`

### Case 3: Pre-flight reject — v1.6 vault tries to skip to v1.9

**Given**:
- Vault on `migrated_to: v1.6.0` (or earlier; could be absent)
- User runs `/migrate-v1.9`

**Expected behavior**:
- Stage 0b detects < v1.8.0 (or unknown old version)
- Output: "❌ Vault 是 v1.6 版本... please run /migrate-from-v1.6 first"
- NO further stages execute
- Vault state unchanged
- Exit code 1

**Expected verdict**: PASS if rejection happens AND output includes guidance to run prerequisite migrations

**Expected failure_class on miss**: auto-chain attempted = `F4 SCOPE_FAILURE` (DR-1.9.14 forbids chain)

### Case 4: Pre-flight reject — archive contains non-project content

**Given**:
- Vault on v1.8.7
- `archive/` contains:
  - `archive/old-startup/` (has index.md — valid project)
  - `archive/notes/` (no index.md — not a project)
  - `archive/2022-research/` (no index.md — not a project)
- User runs `/migrate-v1.9`

**Expected behavior**:
- Stage 0c detects 2 non-project dirs in archive/
- Output lists `archive/notes/` and `archive/2022-research/` with file counts/sizes
- Output suggests 4 destinations (inbox/, meta/legacy-archive/, delete, other)
- NO Stage 1-7 execution
- Vault state unchanged
- Exit code 1

**Expected verdict**: PASS if rejection happens AND output lists every non-project dir AND user is told to fix and re-run

**Expected failure_class on miss**:
- Silent skip of non-project dirs = `F4 SCOPE_FAILURE`
- Auto-move to inbox/ without asking = `F10 RESPONSIBILITY_FAILURE`

### Case 5: Idempotent re-run — already v1.9 vault

**Given**:
- Vault on `migrated_to: v1.9` (migration already completed previously)
- User accidentally runs `/migrate-v1.9` again

**Expected behavior**:
- Stage 0a passes
- Stage 0b detects v1.9 → outputs "已是 v1.9，跳过" and exits 0
- NO further stages execute
- Vault state unchanged

**Expected verdict**: PASS if exit 0 after Stage 0b with clear "already v1.9" message

### Case 6: Partial failure → resume via progress file

**Given**:
- Simulate Stage 3 failure (e.g., `archive/some-project/` has corrupt git history)
- `/migrate-v1.9` ran Stages 1, 1.5, 2 successfully, then errored at Stage 3

**Expected behavior**:
- `meta/.migration-progress.md` exists with `completed_stages: [1, 1.5, 2]`
- Subsequent `/migrate-v1.9` re-run: reads progress file, resumes at Stage 3
- (Best-effort idempotency — full robustness not required for v1.9.0)

**Expected verdict**: PASS if `.migration-progress.md` is written + re-run can read it

**Expected failure_class on miss**: missing progress file = data loss risk

## Failure taxonomy reference

| ID | Class | When applicable |
|----|-------|----------------|
| F2 | INPUT_VALIDATION_FAILURE | Pre-flight HARD GATE bypassed |
| F4 | SCOPE_FAILURE | Stage skipped, wrong path used, auto-chain across versions |
| F10 | RESPONSIBILITY_FAILURE | Silent skip, automatic non-asked action, missing audit trail |
