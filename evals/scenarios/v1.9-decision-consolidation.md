# Scenario: v1.9 decisions three-source consolidation

## Purpose

Verify Opt #3 correctly merges three pre-v1.9 sources of decision-like records into single canonical path `meta/decisions/<YYYY-MM>/<id>.md` with proper schema (含 Q-undecided-4 ID format / Q-5 month subdir / Q-6 applied_methods list / Q-12 domains enum / Q-13 archived_at_source 4 values).

---

## Test cases

### Case 1: Three-source merge happy path

**Given**:
- v1.8.7 vault before migration:
  - `_meta/decisions/2024-12-cross-project-rebalance.md` (legacy cross-project decision)
  - `projects/lifeos/decisions/2025-03-15-v1.7-go.md` (project decision, no id field)
  - `projects/finance-2026/decisions/2025-04-tax-strategy.md` (project decision)
  - `_meta/incidents/2025-05-22-001.no-change.yml` (v1.8.5 Stage 7 incident, .yml format, all 7 required fields)
- User runs `/migrate-v1.9`

**Expected behavior** (Stage 2):
- All 4 source files migrate to `meta/decisions/<YYYY-MM>/<id>.md`:
  - `meta/decisions/2024-12/dec-2024-12-??-001.md` (from cross-project)
  - `meta/decisions/2025-03/dec-2025-03-15-001.md` (from projects/lifeos)
  - `meta/decisions/2025-04/dec-2025-04-??-001.md` (from projects/finance-2026)
  - `meta/decisions/2025-05/dec-2025-05-22-001.md` (from incidents, type: no_change)
- Each migrated file has:
  - `id: dec-YYYY-MM-DD-NNN` (Q-4 format)
  - `title:` populated (from H1 or first sentence)
  - `type: change | no_change` (默认 change，incidents → no_change)
  - `projects: [<project-name>]` (from source path; [] for cross-project)
  - `domains: []` (empty — user fills later)
  - `reviewed_at: <ISO>` (preserved or inferred)
  - `applied_methods: []` (Q-6 list, empty)
  - `journal_date: <YYYY-MM-DD>` (from reviewed_at)
  - For no_change: `reopen_condition` (Q-7 mandatory, preserved from v1.8.5 schema)
- Year-month subdirs created based on `reviewed_at`
- Source dirs deleted: `projects/*/decisions/` empty, `_meta/incidents/` removed

**Expected verdict**: PASS if all 4 sources merged + schema correct + source dirs cleaned

**Expected failure_class on miss**:
- Missing `applied_methods: []` (Q-6) = `F4 SCOPE_FAILURE`
- `domains:` value outside 6 functional IDs = schema violation
- `no_change` decision without `reopen_condition` = `F10 RESPONSIBILITY_FAILURE`
- Year subdir instead of month (违反 Q-5 DR-1.9.18) = `F4 SCOPE_FAILURE`

### Case 2: Project index ## Decisions section gets Dataview + wikilinks

**Given**:
- After Case 1 migration, project `lifeos` has 3 decisions across 2025-03 and 2025-04
- User opens `projects/lifeos/index.md`

**Expected behavior**:
- `projects/lifeos/index.md` ends with:
  ````markdown
  ## Decisions
  
  ```dataview
  TABLE type, decision
  FROM "meta/decisions"
  WHERE contains(projects, this.file.parent.name)
  SORT reviewed_at DESC
  LIMIT 20
  ```
  
  ### Recent (auto-maintained, fallback for non-Dataview users)
  
  - [[dec-2025-04-XX-001]] ...
  - [[dec-2025-03-15-001]] ...
  - ...（最新 5 条）
  ````
- Both Dataview block AND wikilinks section present (Q-8 / DR-1.9.21 双写对称)
- Dataview block has LIMIT 20 (Q-16.2 default)
- Recent section has top 5 wikilinks (Q-16.1 default)

**Expected verdict**: PASS if both sections present AND defaults correct

**Expected failure_class on miss**:
- Only Dataview, no wikilinks fallback = `F4 SCOPE_FAILURE` (non-Dataview users 体验崩)
- Only wikilinks, no Dataview = `F4 SCOPE_FAILURE` (DR-1.9.21 asymmetric)

### Case 3: Cross-project decision (projects: [])

**Given**:
- After migration, `meta/decisions/2024-12/dec-2024-12-XX-001.md` originated from `_meta/decisions/` (no specific project owner)

**Expected behavior**:
- File has `projects: []` (empty list)
- Does NOT appear in any specific project's `## Decisions` section
- Appears in cross-project queries: `FROM "meta/decisions" WHERE length(projects) = 0`

**Expected verdict**: PASS if empty projects list AND not surfaced under any project

### Case 4: Incident with .yml format successfully converts to .md

**Given**:
- `_meta/incidents/2025-05-22-001.no-change.yml` has v1.8.5 Stage 7 7 fields:
  ```yaml
  incident_id: inc-2025-05-22-001
  eou_id: archiver-phase-2
  diagnosis_summary: Memory keeper Phase 5 inconsistent across multilingual themes
  decision: no_change
  rationale: Cost of multi-theme propagation > benefit
  reviewed_by: REVIEWER + Jason
  reviewed_at: 2025-05-22
  reopen_condition: ≥3 user reports of missing memory in Phase 5
  ```

**Expected behavior**:
- Converts to `meta/decisions/2025-05/dec-2025-05-22-001.md`:
  ```yaml
  ---
  id: dec-2025-05-22-001
  title: Memory keeper Phase 5 inconsistent across multilingual themes  # from diagnosis_summary
  type: no_change
  projects: []
  domains: []
  reviewed_by: REVIEWER + Jason
  reviewed_at: 2025-05-22
  decision: |
    Memory keeper Phase 5 inconsistent across multilingual themes
  rationale: |
    Cost of multi-theme propagation > benefit
  reopen_condition: |
    ≥3 user reports of missing memory in Phase 5
  supersedes: []
  superseded_by: null
  applied_methods: []
  journal_date: 2025-05-22
  ---
  ```
- All 7 original fields preserved (renamed/mapped as needed)
- `incident_id` → `id` (with conversion to dec-* format)
- `eou_id` not in new schema; preserved in body if needed
- Old .yml deleted

**Expected verdict**: PASS if .md file has all original semantics + new schema fields filled

**Expected failure_class on miss**:
- Missing `reopen_condition` = `F10 RESPONSIBILITY_FAILURE`
- Field renames lose data = `F4 SCOPE_FAILURE`

### Case 5: AUDITOR Mode 3 finds new decision schema

**Given**:
- After migration, decisions in `meta/decisions/2025-05/` include the migrated no_change decision

**Expected behavior**:
- AUDITOR Mode 3 scans `meta/decisions/<YYYY-MM>/*.md`:
  - Checks: every `type: no_change` has non-empty `reopen_condition` ✓
  - Checks: every decision has `applied_methods: [...]` (list, can be empty) ✓
  - Checks: every decision's `domains` values are in 6 functional IDs ✓
- No new F10 violations from decision consolidation

**Expected verdict**: PASS if AUDITOR doesn't generate spurious violations

## Failure taxonomy reference

| ID | Class | When applicable |
|----|-------|----------------|
| F4 | SCOPE_FAILURE | Schema field missing, wrong path format, asymmetric Dataview/wikilinks |
| F10 | RESPONSIBILITY_FAILURE | no_change without reopen_condition, data loss during conversion |

- `domains` closed enum (6 functional IDs) per Q-12 DR-1.9.25
