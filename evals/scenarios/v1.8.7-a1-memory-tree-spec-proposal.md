# Scenario: A1 — memory-tree-spec frozen as proposal (not implemented)

## Purpose

Verify `references/memory-tree-spec.md` exists as a complete spec proposal AND that v1.8.7 archiver behavior is UNCHANGED (no L0/L1/L2/L3 directory creation, no cascade seal logic activation, no automatic L1/L2/L3 generation).

## Test cases

### Case 1: Spec frozen with correct frontmatter

**Given**: `references/memory-tree-spec.md` shipped in v1.8.7.

**Expected behavior** (AUDITOR Mode 7 spec completeness):
- File exists at `references/memory-tree-spec.md`
- Frontmatter contains `status: proposal` (NOT `active`)
- Frontmatter contains `authoritative: false`
- Frontmatter contains `implementation_target: v1.9 or v2.0 (TBD ...)`
- Frontmatter contains `referenced_by:` pointing to wiki-spec.md + session-index-spec.md + RFC

**Expected verdict**: PASS if all frontmatter fields present.

**Expected failure_class on miss**: `F3 SCHEMA_FAILURE: memory-tree-spec.md missing proposal status markers`.

### Case 2: archiver behavior unchanged

**Given**: archiver runs in v1.8.7 (any adjourn).

**Expected behavior**:
- archiver does NOT create `_meta/sessions/L0/` or any L1/L2/L3 directories
- archiver does NOT run seal logic on existing flat session files
- archiver does NOT call sealing prompts
- archiver Phase 0-4 behavior identical to v1.8.6

**Expected verdict**: PASS if no new directories created AND no seal-related output.

**Expected failure_class on miss**: premature implementation = `F4 SCOPE_FAILURE` (spec is proposal-only in v1.8.7).

### Case 3: wiki-spec + session-index-spec reference proposal

**Given**: v1.8.7 ship state.

**Expected behavior**:
- `references/wiki-spec.md` contains "v2.0 future direction" callout pointing to memory-tree-spec.md
- `references/session-index-spec.md` contains same callout
- Three-language mirrors (i18n/zh + i18n/ja) also contain the callout

**Expected verdict**: PASS if 6 files (3 langs × 2 spec) contain the v2.0 reference line.

**Expected failure_class on miss**: dangling proposal = `F12 DRIFT_FAILURE` (spec exists but not referenced from production-active specs).

### Case 4: Cost calibration disclosed

**Given**: memory-tree-spec.md content review.

**Expected behavior**:
- Spec §"Open questions" includes cost calibration estimate (~$0.50-$2 per L1, ~$2-$10 per L2, $300-$800/year total for active user)
- This is essential context for v1.9/v2.0 implementation decision; missing = incomplete spec

**Expected verdict**: PASS if cost section present.

### Case 5: Migration path is non-destructive

**Given**: spec §"Migration path" review.

**Expected behavior**:
- Migration adds new directories WITHOUT touching existing flat layout
- Existing `_meta/sessions/<sid>.md` paths preserved
- One-time backfill is append-only
- Reversible (can disable cascade and revert to flat reading)

**Expected verdict**: PASS if migration explicitly non-destructive.

## Scope notes

- This scenario is intentionally light because A1 is spec-only in v1.8.7. Full implementation tests will be added in the v1.9/v2.0 RFC that actually builds cascade seal.
- DR-07 mandates A spec validation deferred to real-data runtime, not mock fixtures.
