# Scenario: F12 — WHEN-NOT-TO-ADD anti-pattern boundaries

## Purpose

Verify all 5 WHEN-NOT-TO-ADD.md files exist with three-language mirrors (15 files total) and that adding a new artifact to any of these directories triggers a minimality-rule check.

## Test cases

### Case 1: All 5 × 3 = 15 files exist

**Given**: v1.8.7 ship state.

**Expected behavior** (AUDITOR Mode 7 M7-3):
- `pro/agents/WHEN-NOT-TO-ADD.md` exists
- `references/WHEN-NOT-TO-ADD.md` exists
- `_meta/WHEN-NOT-TO-ADD.md` exists
- `themes/WHEN-NOT-TO-ADD.md` exists
- `scripts/WHEN-NOT-TO-ADD.md` exists
- All 5 have corresponding `i18n/zh/<path>/WHEN-NOT-TO-ADD.md` (5 files)
- All 5 have corresponding `i18n/ja/<path>/WHEN-NOT-TO-ADD.md` (5 files)

**Expected verdict**: PASS if all 15 files exist.

**Expected failure_class on miss**: `F3 SCHEMA_FAILURE: WHEN-NOT-TO-ADD.md missing at <path>` per AUDITOR Mode 7 M7-3.

### Case 2: New agent proposal triggers minimality check

**Given**: User or AI proposes adding `pro/agents/new-helper.md` as a new subagent.

**Expected behavior**:
- AUDITOR Mode 7 M7-3 (or reviewer/planner) reads `pro/agents/WHEN-NOT-TO-ADD.md` first
- Confirms candidate is NOT one of the 6 forbidden categories (generic helper / spec / docs / per-session state / theme / no-v2-frontmatter)
- Applies Minimality Rule 6 questions (rule, schema field, validator, regression case, stop condition, human checklist)
- If any answer is yes → reject new agent; route to lower-cost option

**Expected verdict**: PASS if minimality check applied AND outcome documented.

**Expected failure_class on miss**: new agent landing without minimality check = `F4 SCOPE_FAILURE` per WHEN-NOT-TO-ADD.md "Before adding a new agent" section.

### Case 3: Three-language alignment of WHEN-NOT-TO-ADD docs

**Given**: WHEN-NOT-TO-ADD.md is updated in EN to add a new "don't" item.

**Expected behavior**:
- F11 check 9 (i18n diff parity) detects the EN change
- Verifies `i18n/zh/<path>/WHEN-NOT-TO-ADD.md` and `i18n/ja/<path>/WHEN-NOT-TO-ADD.md` also updated in same/adjacent commit

**Expected verdict**: PASS if mirrors updated; WARN (v1.8.7) if drift.

### Case 4: WHEN-NOT-TO-ADD is itself near-empty

**Given**: User adds 30 items to `pro/agents/WHEN-NOT-TO-ADD.md`.

**Expected behavior**:
- The file's own meta-rule (OpenHuman-borrowed "intentionally near-empty principle") flags itself when exceeding ~10 items
- AUDITOR flags as `WARN: WHEN-NOT-TO-ADD.md getting bloated; review whether items belong elsewhere`

**Expected verdict**: WARN if > 10 items in a single WHEN-NOT-TO-ADD.md file.

## Scope notes

- The 5 WHEN-NOT-TO-ADD.md files are NOT enforcement gates — they're guidance that planner/reviewer/AUDITOR consult before adding new artifacts in those directories.
- Pattern source: OpenHuman `.claude/rules/README.md` "This directory is intentionally near-empty. Stale rules actively mislead agents."
