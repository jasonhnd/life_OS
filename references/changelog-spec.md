# Changelog Guidance

A release entry should help a user understand:

- what changed;
- which behavior is breaking or deprecated;
- what existing data remains compatible;
- whether migration is optional or required;
- what new action, if any, the user must take;
- what was intentionally not published or automated.

Prefer user-observable outcomes over internal process detail. Do not require a
particular heading count, generator, validator, command, or release pipeline.

The repository's release process and publication authority remain separate
from this writing reference.
